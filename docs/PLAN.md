# cloud-courtyard 开发计划

> 一款纪念碑谷风格的推箱解谜游戏。
> 本文是开发期的工作文档，记录已定决策、美术规范、技术架构、里程碑与验证方式。随开发推进更新。

---

## 0. 目标

**基本要求**

- 实现一个推箱子游戏
- 包含**完整的关卡体验流程**和**关卡编辑器**
- 以**产品级**的要求制作

**我们自己的标准**

- 功能达到产品级：流程完整、手感好、边界情况处理到位、有存档、有设置。
- 美术采用**纪念碑谷（Monument Valley）风格**，不用"临时美术"，静态画面和动态效果都要让人眼前一亮。
- 编辑器和游戏同样好看：编辑器里随手画的关卡，也要自动长成一座漂亮的浮空建筑。
- 体现技术策划的能力：数据驱动、工具链（编辑器 + 求解器 + 校验）、可扩展的系统设计、清晰的文档。

暂定游戏名：**《云上庭》Courtyards in the Clouds**（仓库名 `cloud-courtyard`）。

## 2. 美术方向

### 2.1 参考拆解

参考来源：根目录 `参考图/` 三张图 + 纪念碑谷 1/2 官方美术 + ustwo 公开资料（GDC 2015 "The Art of Monument Valley"、MCV 访谈）。

ustwo 公开的做法：
- 全部自写 shader，用**自定义的方向光模型**代替引擎标准光照
- 静态 AO 用烘焙
- 大量叠层做暗角和假体积光
- 正交相机

参考图 2、3 的构图正好是我们要的默认关卡构图：**漂浮城堡顶上的庭院**。游玩区是一块平台，四周是城墙和塔楼，下方是拱门和支柱，整体悬浮在云海之上，远处有淡化的浮岛建筑。

### 2.2 着色规则（MV 质感的核心）

不使用 PBR，所有建筑共用一个自定义 shader `mv_surface.gdshader`：

1. **三面定色**：按面的朝向直接取色，不靠光照计算。
   - 顶面（法线朝上）：最亮
   - 左侧面 / 右侧面：两个不同明度、甚至略不同色相的颜色
   - 用相机空间判断左右，斜面（屋顶、穹顶）在三色之间平滑混合
   - 低面数几何（8 边形穹顶等）自然形成色块分面
2. **世界空间 Y 渐变**：建筑越往下越偏向主题的"深色"（通常偏冷偏紫），表现悬浮感和体积。
3. **高度雾**：再往下融进雾色（与天空地平线颜色一致），支柱消失在云海里。
4. **假 AO（高度图法）**：把关卡每格的高度写进一张低分辨率高度图并模糊。shader 里比较"周围平均高度"和"当前点高度"，墙根、角落、塔楼脚下自然变暗，等效于 MV 的烘焙 AO，但完全程序化，编辑器里实时生效。
5. **彩色软阴影**：只保留投射阴影（箱子、角色、塔楼投到地面），阴影颜色是主题色（偏紫），不用黑色。背光面不再叠加自阴影，避免和三面定色重复变暗。
6. **地砖图案**：地面材质在 shader 里画砖缝和每块砖的细微色差，不额外建模。
7. **后处理**：暗角 + 很淡的纸张颗粒，颗粒顺便消除渐变色带。
8. **色调映射**：Linear，保证色板颜色"所见即所得"。只有超过阈值的自发光（目标点亮、窗户灯光、光柱）才产生 Glow。

### 2.3 建筑语汇

- 墙体 + **浅色压顶收边**（参考图 2 墙顶的浅黄色边）
- 尖拱窗（真实内凹几何，内壁按法线自动着色，产生纵深）
- 拱门、拱廊、台基下的大拱券
- 塔楼 + 屋顶：方锥顶、洋葱顶、中式攒尖顶（按主题选择）
- 台阶、水渠、瀑布、樱花树（低面数树冠）
- 悬挂在台基下方的倒锥形支柱 / 层叠底座
- 远景：同一套生成器生成的小型浮岛建筑，高度淡化

### 2.5 角色设计：斗笠旅人

- 身高约 0.75 格，剪影优先：宽檐斗笠 + 圆锥形斗篷 + 两条细腿
- 斗笠为草黄色，斗篷米白；一条长围巾随主题点缀色变化，带二级摆动（弹簧模拟）
- 面部藏在斗笠阴影里，只露一点浅色下巴，保持神秘感、不需要表情动画
- 全部用程序几何拼装，使用同一套 MV shader，和场景风格统一

### 3.1 环境动态（常驻）

| 元素 | 实现 |
|---|---|
| 水渠流水 | 水面 shader：UV 流动条纹 + 边缘浅色 + 细微波纹 |
| 瀑布 | 竖直条带 shader 下落条纹；底部泡沫圈 + 水雾粒子 |
| 云海 | 台基下方多层半透明云片（软噪声 shader），缓慢漂移，部分遮住支柱 |
| 远景浮岛 | 缓慢上下浮动，高度淡化 |
| 花瓣 / 光尘 | 少量 GPU 粒子缓慢飘落 |
| 树 | 顶点 shader 风吹摆动 |
| 角色待机 | 呼吸起伏 + 围巾飘动，偶尔转头 |

### 3.2 交互反馈

| 事件 | 动画 | 特效 | 音效 |
|---|---|---|---|
| 行走 | 0.16s/格，小幅弹跳（正弦弧 + 轻微挤压拉伸），朝向平滑转身 | 脚下极淡尘土 | 轻柔脚步 tick（随机音高） |

### 3.3 关卡演出

- **入场搭建**：台基、墙、塔楼从云雾中依次升起拼合（按距中心的距离错开时间，ease-out-back 回弹）。随后箱子落下，角色在光点中现身。标题卡淡入淡出：罗马数字 + 关卡名。
- **通关"机关苏醒"**：
  1. 所有目标依次波纹式闪亮，奏出上行琶音
  2. 塔楼窗户逐个点亮
  3. 水渠涌水、瀑布加大，樱花树开花并爆出花瓣
  4. 一段隐藏的台阶从平台边缘逐级展开，伸向云海
  5. 角色转身欢呼
  6. 镜头缓慢拉远
  7. 结算面板淡入：步数、推动次数、最佳记录、参考最优步数

### 4.2 逻辑层与表现层分离

- **逻辑层**（`scripts/core/`）是纯 2D 网格推箱子，不知道任何 3D 的存在。
  - 格子类型：`VOID`（虚空）/ `FLOOR` / `WALL`
  - 叠加层：目标、箱子、玩家
  - 箱子有稳定的 id，表现层靠 id 对应 3D 节点做动画
  - 每次操作返回结构化结果：`moved` / `pushed_box_id` / `blocked_by`（墙或箱子）/ `box_entered_target` / `box_left_target` / `solved`
  - 无限撤销/重做，统计步数和推动次数
- **表现层**只监听逻辑结果来播放动画。动画期间的新输入进入**输入缓冲**（缓存 1 步），保证手感灵敏。
- 高度、建筑、水、树全部是装饰，**不影响规则**。

### 4.3 关卡数据格式

内置与自定义关卡都用 JSON，地图部分兼容推箱子社区标准 **XSB** 字符：

```json
{
  "format": 1,
  "id": "01",
  "name": "初见",
  "name_en": "First Light",
  "theme": "dawn",
  "seed": 1024,
  "par_moves": 14,
  "par_pushes": 4,
  "map": [
    "  #####",
    "###---#",
    "#-$-.-#",
    "#-@---#",
    "#######"
  ]
}
```

| 字符 | 含义 |
|---|---|
| `#` | 墙 |
| `-` / `_` | 地板（显式） |
| 空格 | 虚空。导入经典 XSB 时，从玩家位置泛洪填充，可达的空格判为地板 |
| `.` | 目标 |
| `$` | 箱子 |
| `*` | 箱子在目标上 |
| `@` | 玩家 |
| `+` | 玩家在目标上 |

- `seed` 控制程序化装饰的随机性，保证同一关每次生成完全一致。
- `par_moves` / `par_pushes` 由求解器写入，用于结算评价。
- 编辑器支持直接粘贴/导出 XSB 文本，可以导入经典关卡。

### 4.4 坐标与相机

- 网格坐标 `(col, row)` 映射为世界坐标 `(x = col, z = row)`，地面 y = 0。
- 正交相机，真等轴视角：俯仰 −35.264°，偏航 45°，从 (+x, +y, +z) 方向看向关卡中心。
  - 屏幕上看到 +X 面（右前）、+Z 面（左前）和顶面
  - XSB 地图整体顺时针旋转 45° 成菱形呈现
- 相机根据关卡包围盒自动适配缩放；通关时缓慢拉远。

### 4.5 程序化装饰规则（MonumentBuilder）

这是保证"编辑器做的关卡也好看"的关键。输入：关卡网格 + 主题 + seed，输出：一座完整的浮空建筑。

1. **台基**：所有非虚空格下方生成厚台基。可见的两个侧面（+X、+Z）开拱形凹龛和小窗，底部收成层叠/倒锥形，向下延伸进雾里。
2. **遮挡判定**：等轴视角下，位于 `(c, r)`、高度为 h 的物体会遮挡其"后方"的格子 `(c−k, r−k)` 及两侧相邻格（k 由 h 决定）。所有高大装饰都要通过 `occludes_play(cell, height)` 检查，**不得遮挡任何可玩格**。
3. **墙体高度**：
   - 后方无可玩格的外墙 → 高墙（≈1.0），可加城垛
   - 内部障碍墙和前侧外墙 → 矮墙（≈0.5），保证视线
   - 所有墙带浅色压顶，压顶只在不与相邻墙相接的一侧外挑
4. **塔楼**：放在建筑轮廓的凸角上。按遮挡判定，只放在上、左、右三个方位，正下方的角放低矮元素（台阶、亭子）。塔楼 = 塔身 + 尖拱窗 + 主题屋顶。
5. **水**：选取轮廓边缘的一段外墙改为水渠，水从边缘泻下形成瀑布，落入云海。
6. **植物**：在不遮挡的墙顶或塔基放樱花树/盆栽。
7. **远景**：环绕主建筑生成 4~6 座小浮岛（同一生成器，缩小 + 高度淡化），缓慢浮动。
8. **云**：主建筑下方与远景之间放多层云片。
9. **性能**：复杂构件（拱、窗）用 CSG 搭建后 `bake_static_mesh()` 烘成静态网格；编辑器中实时重建时先出简化版，停笔 0.3s 后补全装饰。

### 4.6 渲染管线

- `WorldEnvironment`：
  - 背景模式 `Canvas`，天空用 2D CanvasLayer 绘制（渐变、太阳、星星）。正交相机下 3D 天空球会退化成单色，所以不用。
  - Linear 色调映射、Glow（高阈值）、关闭环境光（由 shader 完全控制颜色）
- `DirectionalLight3D`：只负责投射阴影。软阴影（PCSS / 高质量过滤），阴影方向让影子落向屏幕左下方。
- MSAA 4x，开启 debanding。
- 全局 shader 参数（`[shader_globals]`）：雾色、深色、雾高度范围、阴影色、AO 高度图及其世界范围。切换主题时统一更新。
- 后处理：CanvasLayer 全屏 shader 做暗角和颗粒。

### 4.7 输入

| 操作 | 按键 |
|---|---|
| 移动 | `W/↑`：网格上（屏幕右上）；`D/→`：网格右（屏幕右下）；`S/↓`：网格下（屏幕左下）；`A/←`：网格左（屏幕左上）。HUD 角落显示方向罗盘提示 |
| 点击移动 | 点击地面 → BFS 寻路走过去（不推箱）；点击相邻箱子 → 朝该方向推一次；悬停时高亮目标格和路径 |
| 撤销 / 重做 | `Z` / `Y`（也支持 `Ctrl+Z` / `Ctrl+Shift+Z`） |
| 重开 | `R` |
| 暂停 | `Esc` |

- 输入映射在 `Game` autoload 中用代码注册。
- 按住方向键可连续移动。

### 4.8 存档与设置

- `user://progress.json`：每关是否完成、最佳步数、最佳推动次数，以及已解锁关卡。
- `user://settings.json`：主音量 / 音乐 / 音效、全屏、颗粒效果开关。
- 自定义关卡保存到 `user://levels/*.json`，在选关界面的"工坊"分区显示。

## 5. 游戏流程与 UI

```
标题界面 ──► 选关 ──► 关卡（HUD） ──► 通关结算 ──► 下一关 / 重玩 / 返回选关
   │           │           │
   │           │           └─ 暂停菜单（继续 / 重开 / 设置 / 返回）
   │           └─ 工坊（自定义关卡）
   └─ 关卡编辑器 ──► 试玩 ──► 返回编辑器
   └─ 设置
```

- **标题界面**：背景是缓慢环绕的浮空建筑，标题字和一行英文小字，菜单项为纯文字，悬停时出现下划线动画。
- **选关**：5 座微缩浮岛（同一生成器生成）沿斜线排列，相机平移切换。显示关卡名、主题、完成状态和最佳步数；未解锁的浮岛隐在雾中。
- **HUD**：左上关卡名，右上步数和推动次数，底部撤销/重开/菜单图标按钮。极简、半透明，不抢画面。
- **UI 风格**：
  - 字体：衬线体（中文思源宋体子集化，西文 Cormorant Garamond，均为 OFL）
  - 半透明白色面板 + 细线
  - 所有界面切换带淡入和位移动画
- **双语**：中文为主，英文副标题点缀。

## 6. 关卡编辑器

游戏内编辑器，和游戏使用**同一套渲染与程序化建筑**：编辑即所见。

**画布**

- 等轴 3D 视图，虚空区域显示淡淡的网格虚线，鼠标悬停的格子有发光描边
- 地图尺寸可调（最大 16×16），也可以随时切换到俯视 2D 视图，方便精确编辑

**工具栏**（快捷键 1–7）

- 地板、墙、箱子、目标、玩家、擦除（变回虚空）、吸管
- 左键绘制、右键擦除，支持拖拽连续绘制、矩形填充（Shift 拖拽）

**编辑操作**

- 撤销/重做（按笔划记录）
- 新建、清空、调整尺寸、选择主题、修改关卡名
- 换装饰种子：同一关卡换一种建筑生成方式

**实时校验面板**

- 玩家数量必须为 1
- 箱子数 = 目标数 ≥ 1
- 所有箱子和目标位于玩家可达区域内
- 地图被墙封闭，不会走出边界
- 简单死局检测：箱子初始就在不可推出的死角

**求解器**（按钮触发，后台线程运行）

- 显示"可解，最优 N 步 / M 次推动"或"无解"或"超出搜索上限"
- 可以一键回放最优解

**其他**

- **试玩**：一键进入游戏模式，按 Esc 回到编辑器，编辑状态完整保留
- **保存/加载**：保存为 JSON 到 `user://levels/`，可以在选关的"工坊"里游玩
- **XSB 导入/导出**：复制到剪贴板、从剪贴板粘贴

## 7. 求解器

- **算法**：以推箱为扩展单位的 A*，代价 = 行走步数 + 推动次数。
  - 状态 = 箱子集合 + 推箱后玩家的精确位置
  - 从当前状态 BFS 求出玩家到每个推箱位的距离，作为该次推箱的代价
- **启发函数**：每个箱子到最近目标的推动距离之和（可采纳），保证结果是步数最优。
- **剪枝**：
  - 死格预计算：从目标反向"拉箱"不可达的格子
  - 2×2 死锁检测
- **工程化**：
  - GDScript 实现，放在 `WorkerThreadPool` 线程运行，不卡 UI
  - 有状态数和时间上限
  - 同时提供 Python 版 `tools/solver.py`，用于离线设计和验证关卡
- **用途**：编辑器校验、生成关卡 par 值、游戏内提示（可选：按 H 高亮下一次推箱）。

## 9. 关卡设计

| # | 主题 | 箱子数 | 目标步数 | 教学点 |
|---|---|---|---|---|
| 1 | 晨曦 | 1–2 | ≤ 15 | 移动和推箱的基本规则 |
| 2 | 碧水 | 2 | 20–35 | 箱子推进角落就无法推出 |
| 3 | 暮霞 | 3 | 40–60 | 推箱的顺序很重要 |
| 4 | 紫境 | 3–4 | 60–90 | 狭窄通道中的调度 |
| 5 | 星夜 | 4–5 | 80–150 | 综合规划，有挑战但不劝退 |

- 原创设计，不抄已出版的关卡集。
- 平台形状要有建筑感（L 形、回字形庭院、内部立柱），避免方方正正。
- 可玩格控制在约 45 格以内，保证求解器能快速验证。
- 每关都用求解器验证可解，并写入 par 值。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 等轴视角下墙/塔遮挡可玩区域 | 遮挡判定 + 墙高规则；必要时对遮挡物做抖动透明 |
| GDScript 求解器性能 | A* + 死格剪枝 + 线程 + 上限；关卡规模控制在 ~45 格 |
| CSG 实时重建卡顿 | 烘焙静态网格；编辑器分级重建（防抖） |
| 中文字体体积大 | fonttools 子集化，用户输入走系统字体回退 |
| 自定义 shader 在不同 GPU 上表现不一 | 只用基础特性；交付前在干净环境验证 |
| 美术追求导致范围膨胀 | 按里程碑推进；每阶段先保证可运行，再迭代质感 |
| 版权 | 全部原创/程序生成，参考图不进仓库 |
